# ドキュメント最小再構築（Rust特化）

**対象範囲**: $ARGUMENTS（未指定なら `git diff HEAD` の変更範囲）

## 前提

既存のコメントはコードに追従していないことが多い。現在のコード（型・シグネチャ・制御フロー）だけを唯一の情報源とし、対象範囲のコメントを一度すべて削除してからゼロで書き直す。ドキュメントは保守コストになるため、量より正確さ、原則最小限に留める。

対象は行コメント（`//`）・ブロックコメント（`/* */`）・doc コメント（`///` `//!`）・`// SAFETY:` と doctest のみ。コードそのものは変更しない。

## 書かないもの

- 既存コメントの要約・編集による引き継ぎ
- WHAT/HOW、会話由来の思想、旧APIとの差分、呼び出し元・利用箇所の説明
- 太字/体言止め+コロンの強調表現

## 書くもの

- 使い方や挙動は長文の説明ではなく `# Examples` の doctest で表現する
- 公開 API・非公開の項目ともに必要最低限の記述に留める
- どうしても文章が必要な場合も、コードから読み取れる最重要点のみを1、2文で書く
- その他の書き方（`// SAFETY:` の要件、改行・句読点のルールなど）は `rust-coder` スキルに従う

## 実行手順

1. 対象範囲を確定し、既存コメントを一度すべて削除する
2. コメントを削除したコード（型・シグネチャ・制御フロー）だけを見て、doc コメント・SAFETY コメント・doctest をゼロから設計する
3. 「書かないもの」に該当する記述、および不自然な改行が残っていないか確認する。コードの挙動と既存コメントの記述が食い違う箇所（不具合の疑い）を見つけたら、正しい挙動として文書化せず「要確認」に挙げ、`/thought-bug` での原因特定を提案する
4. `cargo test --doc` を実行し、doctest が通ることを確認する

## 出力形式

**削除した不要コメント**（ファイルと箇所、どういうコメントか） / **追加・改善した doctest**（doctest で表現した仕様） / **残した最小限のコメント**（残す必要があった WHY・SAFETY） / **検証結果**（`cargo test --doc` の結果と、不自然な改行がないか） / **要確認**（コードと既存コメントの記述が食い違い不具合が疑われる箇所。なければ「なし」）
