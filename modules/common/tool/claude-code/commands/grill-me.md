この計画のあらゆる側面について、私たちが共通の認識に達するまで、徹底的に私に質問を投げかけてください。
設計のツリーを枝分かれの先まで一つひとつたどり、決定事項間の依存関係を順番に解決していきましょう。

手順:

1. まずコードベースを軽く調査し、方針が大きく変わりうる論点がないか確認する。あればAskUserQuestionでまとめて質問する。なければこのステップは飛ばしてよい。
2. その回答（または1を飛ばした場合は最初の計画内容）を踏まえて、詳細なコードベース調査を行う。
3. 調査結果をもとに残りの論点を洗い出し、AskUserQuestionでまとめて質問する。選択肢を提示できる質問は必ずAskUserQuestionを使い、推奨する選択肢には「(推奨)」を付ける。地の文での自由記述質問は、ユーザーの自由入力をもとに検討したい場合のみ使う。
4. 回答によってさらに調査すべき点が生じたら、2〜3を繰り返す。

もしコードベースを探索することで答えが得られる質問であれば、質問する代わりにコードベースを調査してください。

調査の過程で、この計画とは別に原因不明の既存バグを発見した場合は、その場で深追いせず `/thought-bug` の使用を提案してください。

共通の認識に達したら、決定事項をMarkdownファイルにまとめて、claude-code起動時のカレントディレクトリ直下に書き出してください。このファイル単体を渡せば別セッション・別コンテキストからでも作業に着手できるように、以下を含めてください。

- 合意した設計・決定事項とその理由
- 実装に必要な調査結果・コンテキスト
- 参照すべきファイル・パス
- 残っている未解決点（あれば）

Rustの実装に関する計画であれば、`/impl-rust` にそのまま渡せる仕様書として書いてください（実装方針・コメント方針は `rust-coder` スキルに準拠する前提で書く）。
