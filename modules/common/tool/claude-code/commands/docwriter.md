# ドキュメント最小再構築（Rust特化）

**対象範囲**: $ARGUMENTS（未指定なら `git diff HEAD` の変更範囲）

## 前提

既存のコメントはコードの変更に追従していないことが多いため、内容を一切当てにしない。現在のコードの型・シグネチャ・制御フローだけを根拠に、必要な部分をゼロから書き直す。
ドキュメントは書くほど保守コストになるため、量より正確さを優先し、原則として最小限に留める。

## 書かないもの

- 既存の文章の要約・編集による引き継ぎ。一度すべて削除してから書き直す
- コードを読めば分かること。変数名・型・関数分割で表現できるならコメントは不要
- 言語仕様・標準ライブラリの挙動・`Send`/`Sync` の一般的なイディオムのような自明な説明
- 会話で伝えた設計意図・思想の転記。会話は陳腐化前提の一時的な文脈であり、リポジトリ内の情報だけで理解できる記述に変換する
- 「以前は〜だった」「〜から変更された」のような旧APIとの差分・変更履歴。git log・git diff の領域であり、ドキュメントは現在のコードの状態のみを説明する
- 「このクレートの〜で使われる」「ここでは〜のために呼ばれる」のような呼び出し元・利用箇所の説明。利用状況は陳腐化するため、対象自体の入力・出力・不変条件のみを書く
- 太字（`**`）や体言止め＋「：」を多用する箇条書き的な強調表現。読点・句点を使った通常の文章として書く
- 文の区切りとしての `;`。意味が正しく伝わらないため `,` または `.` のみを使う

## 書くもの

- 使い方や挙動は、長文の説明ではなく `# Examples` の doctest で表現する
- 公開 API・非公開の項目ともに、必要最低限の記述にとどめる
- `// SAFETY:` は、呼び出し側・実装側が満たすべき非自明な前提条件がある場合のみ書く
- どうしても文章が必要な場合も、既存の文章は読まず、コードから読み取れる最重要点のみを1〜2文程度で書く
- 1文は改行せず1行で書く。改行してよいのは箇条書きの項目間、見出しの前後、コードブロックの前後、および1文が150文字を超え途中で区切る必要がある場合のみ。段落の途中に無駄な空行を挟まない

対象は行コメント（`//`）・ブロックコメント（`/* */`）・doc コメント（`///` `//!`）・`// SAFETY:` と doctest のみ。コードそのものは変更しない。

## 実行手順

1. 対象を確定し、その範囲の既存コメントを一度すべて削除する
2. コメントを削除したコード（型・シグネチャ・制御フロー）だけを見て、必要な doc コメント・SAFETY コメント・doctest をゼロから設計する。既存の文章・会話の履歴は参照しない
3. 会話由来の思想・旧APIとの差分・呼び出し元の説明・太字や「：」の強調・不自然な改行が混入していないか見直す
4. `cargo test --doc` を実行し、doctest が通ることを確認する

## 出力形式

**削除した不要コメント**（ファイルと箇所、どういうコメントか） / **追加・改善した doctest**（doctest で表現した仕様） / **残した最小限のコメント**（残す必要があった WHY・SAFETY） / **検証結果**（`cargo test --doc` の結果と、不自然な改行がないか）
