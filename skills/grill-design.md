# 設計思想のグリル

**テーマ**: $ARGUMENTS（未指定なら直前の会話や直近の差分から推測）

`/grill-me` を土台とし、調査を質問より優先する・推奨案を必ず添える原則を引き継ぐ。加えて、実装・コード変更は行わない。意図はコードから逆算せず必ずユーザー自身の説明を起点にする（明示されていなければAskUserQuestionで直接聞く）。事実（`ファイル名:行番号` 根拠）と推測・提案は分けて書く。

対象に複数の設計判断が含まれる場合も一論点ずつ提示し、ユーザーと合意してから次に進む。対抗案は現状のコード構造・依存関係への追従を前提とせず、ユーザーの意図を最も実現する設計を優先する。

## 論点ごとの出力

ユーザーの意図 / 現状の設計（根拠付き）/ 意図とのギャップ / 現状設計の制約・理由の推測（根拠がなければ「推測」と明示）/ 対抗案（案A・案Bそれぞれ意図の実現度・利点・欠点）/ 推奨（現状維持が最善ならその理由）。

全論点で合意（または保留）に達したら結論を列挙して締める。設計変更したい場合は `/grill-rust` や `/impl-rust` などの実装系スキルへの引き継ぎを提案する。ファイル保存は明示的に依頼された場合のみ行う。
