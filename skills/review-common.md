# レビュー共通方針

`/pr-review` `/review-code` `/review-doc` から読み込まれる共通方針。各スキル固有の定義と矛盾する場合はスキル側を優先する。直接呼び出された場合は以下をそのまま提示する。

## 基本姿勢

指摘は「問題の説明 + 改善提案」をセットで行い、スタイル・好みと実際のバグ・リスクを区別する。良い点も必ず言及し、明示的に求められない限り書き直さない（修正は実装系スキルに委ねる）。

## コードレビュー観点（pr-review / review-code 共通）

正確性（ロジックのバグ・エッジケース）、安全性（OWASP Top 10）、可読性（命名・複雑度）、保守性（重複・責務分離）、パフォーマンス（不要な計算・N+1）、テスト（網羅性・エッジケース）。

重要度: 高=バグ・セキュリティ・データ損失リスク / 中=パフォーマンス・保守性低下・テスト漏れ / 低=可読性・スタイル・軽微な改善。

## 出力フォーマットの骨格

良い点 → 指摘事項（`- **[重要度: 高/中/低]** 場所 — 問題 → 改善提案`）→ サマリー。節名・場所の示し方はスキルごとに読み替える（review-docは「改善点」、場所はファイル名:行番号ではなく該当箇所）。
